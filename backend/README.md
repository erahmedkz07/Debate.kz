# Debate.kz — backend

REST API платформы дебатных турниров.

**Стек:** Node.js 24 · Express 5 · TypeScript · Prisma 7 (`@prisma/adapter-pg`) · PostgreSQL 16 · zod · bcrypt · JWT (httpOnly cookie)

## Первый запуск (Windows)

```powershell
cd backend
npm install
copy .env.example .env      # затем задайте пароль БД и JWT_SECRET (см. комментарии в файле)
```

Создать пользователя и базу PostgreSQL (один раз):

```powershell
# если знаете пароль суперпользователя postgres
powershell -ExecutionPolicy Bypass -File scripts\setup-db.ps1
# если НЕ знаете — из PowerShell "от имени администратора":
# временно открывает локальный вход, создаёт роль/базу и всегда возвращает настройки обратно
powershell -ExecutionPolicy Bypass -File scripts\setup-db-admin.ps1
```

Оба скрипта берут логин, пароль и имя базы из `.env` и отказываются работать с базой, которая принадлежит другой роли (например, от старой версии проекта).

Таблицы, демо-данные и запуск:

```bash
npx prisma migrate dev      # применяет миграции
npm run db:seed             # демо-данные в ПУСТУЮ базу (если в базе уже есть пользователи — откажется)
npm run db:seed:force       # сброс к демо-данным: стирает всё, только осознанно
npm run dev                 # http://localhost:4000, перезапуск при изменениях
```

Фронтенд (`../frontend`, `npm run dev`) проксирует `/api` на этот сервер.

## Роли и права

Глобальных ролей две: **`user`** (все после регистрации) и **`admin`**. Организатор и судья — это не роли,
а права внутри конкретного турнира:

| Право | Как получить | Что даёт |
|---|---|---|
| Владелец турнира | создать турнир (нужен подтверждённый email, не больше 3 активных) | всё в своём турнире, в т.ч. удаление и приглашение соорганизаторов |
| Соорганизатор | одноразовая ссылка-приглашение от владельца | управление турниром без удаления и приглашения организаторов |
| Судья | одноразовая ссылка-приглашение от организатора | бюллетени только своих дебатов в этом турнире |
| Участник команды | заявка, подтверждённая организатором | выступать |
| Админ | `npm run admin:grant -- email@…` или другой админ | модерация турниров, оплата Pro, пользователи |

- Регистрация не принимает роль (поле `role` игнорируется) и требует согласия на обработку персональных данных.
- Создать турнир, подать заявку и принять приглашение можно только после подтверждения email.
  Сейчас письма печатаются в консоли сервера (`src/lib/mail.ts`); для продакшена замените транспорт на SMTP.
- Новый турнир виден в общем списке только после одобрения админом; при отклонении нужна причина, владелец получает письмо.
- Конфликт интересов блокируется: в одном турнире нельзя быть и участником команды, и судьёй/организатором.

## Уведомления

Каждое событие создаёт запись в центре уведомлений (`notifications`: тип + данные, текст собирается на сайте на RU/KZ)
и дублируется в Telegram тем, кто подключил бота (`src/services/notify.ts`). Получатели — по правам в конкретном турнире:

| Кому | Что |
|---|---|
| Участник (спикер/заявитель) | решение по заявке, жеребьёвка (аудитория, сторона, соперник, тема), итог раунда |
| Судья | назначение на дебат (роль, аудитория, ссылка на бюллетень), приветствие после принятия приглашения |
| Организаторы турнира | новая заявка, кто принял приглашение, одобрение/отклонение/удаление турнира |
| Админы | турнир ждёт проверки (с пометкой Pro) + лента всей платформы |

## Вход через Google

Кнопки «Войти / Зарегистрироваться через Google» появляются на сайте, только когда в `.env` заданы ключи.
Код — `src/routes/google.ts` (OAuth 2.0 + OpenID Connect на сервере: `state` против CSRF, `nonce` против повтора,
PKCE, проверка издателя/получателя/срока токена и `email_verified`). Токены Google не хранятся — только id аккаунта,
email, имя и фото (фото перекодируется в WebP, как обычный аватар).

**Настройка (один раз, в своём Google-аккаунте):**
1. Откройте [Google Cloud Console](https://console.cloud.google.com/) → создайте проект (например, «Debate.kz»).
2. **APIs & Services → OAuth consent screen**: тип *External*, название приложения, email поддержки;
   scopes — `openid`, `email`, `profile` (больше не нужно). Пока приложение в режиме *Testing*, войти могут только
   адреса из списка *Test users* — добавьте туда свои; для всех пользователей нажмите *Publish app*.
3. **APIs & Services → Credentials → Create credentials → OAuth client ID**, тип *Web application*:
   - *Authorized JavaScript origins*: `http://localhost:5173` (и боевой адрес, например `https://debate.kz`);
   - *Authorized redirect URIs*: `http://localhost:5173/api/auth/google/callback` (и `https://debate.kz/api/auth/google/callback`).
     Адрес строится из `CLIENT_ORIGIN`, он должен совпадать символ в символ.
4. Скопируйте *Client ID* и *Client secret* в `backend/.env` (секрет никому не пересылайте):
   ```
   GOOGLE_CLIENT_ID=1234-abc.apps.googleusercontent.com
   GOOGLE_CLIENT_SECRET=GOCSPX-...
   ```
5. Перезапустите бэкенд.

**Правила:**
- новый пользователь создаётся с подтверждённым email, именем и фото из Google и попадает в профиль дописать телефон, школу и город;
- если аккаунт с таким email уже есть — Google привязывается к нему (пароль продолжает работать). Если email этого аккаунта
  не был подтверждён, прежний пароль сбрасывается и все сессии завершаются: так чужой человек, заранее зарегистрировавший
  ваш адрес, не сохранит доступ;
- в профиле Google можно подключить (даже с другим адресом) и отключить — отключить можно, только когда задан пароль;
- у аккаунта «только Google» пароля нет: «Задать пароль» присылает ссылку на почту; удаление аккаунта подтверждается вводом email;
- о привязке/отвязке Google и смене пароля владельцу приходит письмо.

## Почта

Без настроек письма печатаются в консоль бэкенда. Чтобы они реально приходили (в том числе на Gmail), заполните SMTP в `.env`
(`src/lib/mail.ts`, шаблоны писем — `src/services/letters.ts`). Сбой почты не ломает запрос: ошибка пишется в лог.

**Gmail (для начала):**
1. В Google-аккаунте, с которого будут уходить письма, включите [двухэтапную аутентификацию](https://myaccount.google.com/signinoptions/two-step-verification).
2. Создайте [пароль приложения](https://myaccount.google.com/apppasswords) (16 букв). Обычный пароль от Gmail сюда не подходит.
3. Впишите в `backend/.env`:
   ```
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=465
   SMTP_USER=your.address@gmail.com
   SMTP_PASS=abcdefghijklmnop
   MAIL_FROM=Debate.kz <your.address@gmail.com>
   ```
Gmail отправляет до ~500 писем в сутки — для старта хватит; для боевого сайта лучше отдельный сервис рассылок
(SMTP-настройки те же, меняются только значения).

**Какие письма уходят:** подтверждение email, восстановление пароля, «задайте пароль» (для аккаунтов через Google),
«пароль изменён/задан», «добро пожаловать» (регистрация через Google), «Google подключён/отключён».
В тестах (`npm run test:e2e`) SMTP принудительно выключен, письма складываются в память и читаются через `/api/test/mail`.

## Telegram-бот

Бот — дополнение к сайту (`src/services/bot.ts`, `src/services/notify.ts`, `src/lib/telegram.ts`). Без токена он выключен,
сайт работает как обычно.

**Настройка (один раз):**
1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → имя (например, «Debate.kz») → username, который оканчивается на `bot` (например, `DebateKzBot`).
2. BotFather пришлёт токен вида `123456789:AA...`. **Никому его не пересылайте** (и не вставляйте в чаты) — с ним можно управлять ботом.
3. Впишите в `backend/.env`:
   ```
   TELEGRAM_BOT_TOKEN=123456789:AA...
   TELEGRAM_BOT_USERNAME=DebateKzBot
   ```
4. Перезапустите бэкенд — в консоли появится `Telegram bot @DebateKzBot started (long polling)`.

Бот работает через long polling (публичный адрес не нужен). Одновременно токен может опрашивать только один процесс.

**Что умеет:**
- привязка аккаунта: «Подключить Telegram» в профиле → одноразовая ссылка `t.me/<бот>?start=<токен>` (15 минут, хранится только хеш);
- подтверждение телефона кнопкой «Поделиться номером»: принимается только свой контакт, номера +7 7xx, один номер — один аккаунт;
- уведомления: жеребьёвка (аудитория, сторона, соперник, тема; судьям — роль и ссылка на бюллетень), решение по заявке, решение модерации;
- команды `/me`, `/stop`, `/on`; группы игнорируются; если пользователь заблокировал бота, чат отвязывается.

Сообщения пишутся только тем, кто сам подключил бота. В тестовом режиме (`NODE_ENV=test`) сообщения не уходят в Telegram,
а складываются в память — e2e играет роль Telegram через `/api/telegram/test/*` (в других режимах этих путей нет).

## Правила, которые проверяет сервер

- Спикеры 60–80, ответная речь 30–40, шаг 0,5; ничьих нет; победитель = команда с большей суммой.
- Ответную речь говорит только 1-й или 2-й спикер.
- Судьи голосуют каждый за себя, решает большинство; при равенстве голосов — председатель.
  Если бюллетень вносит организатор (бумажный бюллетень), он сразу фиксирует результат.
- Раунд публикуется только с темой и жеребьёвкой; завершается, когда у всех дебатов есть результат; после завершения бюллетени закрыты.
- Жеребьёвка: по силе (победы → баллы спикеров), без повторных встреч, с балансом сторон; один судья — одна комната за раунд; судья не судит свою школу.
- Организатор управляет только своими турнирами; заблокированный пользователь теряет доступ сразу.
- Этапы турнира: регистрация → идёт → завершён (назад в регистрацию — пока не опубликован раунд); нужен одобренный турнир и 2+ команды.
- Лимит команд не ниже числа команд в турнире; больше 12 — тариф Pro (оплату подтверждает админ).
- Swing-команда (добавляется при нечётном числе команд) не входит в таблицу, лимиты и счётчики команд.
- Тариф: все функции бесплатны; турнир больше 20 команд — Pro. Пока Pro не оплачен, турнир принимает не больше 20 команд (402 `payment_required`).
- Заявку на турнир можно подать только с клубом и командой в профиле (`club_required`); команда турнира запоминает клуб.
- Жеребьёвка: методы power / high_low / random (`POST /rounds/:id/draw { method, protectClubs }`). В раундах 1–2 по умолчанию команды одного клуба (или одной школы) не встречаются; если чистый вариант невозможен, делается минимум таких встреч, а ответ `report` говорит сколько (`services/pairing.ts`).
- Ответственного за безопасность назначает админ (`PATCH /admin/users/:id { safeguardingOfficer }`, пишется в журнал).
  В Telegram о новом обращении приходит только сигнал без подробностей.
