# Debate.kz — backend

REST API платформы дебатных турниров.

**Стек:** Node.js 24 · Express 5 · TypeScript · Prisma 7 (`@prisma/adapter-pg`) · PostgreSQL 16 · zod · bcrypt · JWT (httpOnly cookie)

## Первый запуск (Windows)

```powershell
cd backend
npm install
copy .env.example .env      # затем задайте пароль БД и JWT_SECRET (см. комментарии в файле)
```

Создать пользователя и базу PostgreSQL (один раз):

```powershell
# если знаете пароль суперпользователя postgres
powershell -ExecutionPolicy Bypass -File scripts\setup-db.ps1
# если НЕ знаете — из PowerShell "от имени администратора":
# временно открывает локальный вход, создаёт роль/базу и всегда возвращает настройки обратно
powershell -ExecutionPolicy Bypass -File scripts\setup-db-admin.ps1
```

Оба скрипта берут логин, пароль и имя базы из `.env` и отказываются работать с базой, которая принадлежит другой роли (например, от старой версии проекта).

Таблицы, демо-данные и запуск:

```bash
npx prisma migrate dev      # применяет миграции
npm run db:seed             # демо-данные в ПУСТУЮ базу (если в базе уже есть пользователи — откажется)
npm run db:seed:force       # сброс к демо-данным: стирает всё, только осознанно
npm run dev                 # http://localhost:4000, перезапуск при изменениях
```

Фронтенд (`../frontend`, `npm run dev`) проксирует `/api` на этот сервер.

## Роли и права

Глобальных ролей две: **`user`** (все после регистрации) и **`admin`**. Организатор и судья — это не роли,
а права внутри конкретного турнира:

| Право | Как получить | Что даёт |
|---|---|---|
| Владелец турнира | создать турнир (нужен подтверждённый email, не больше 3 активных) | всё в своём турнире, в т.ч. удаление и приглашение соорганизаторов |
| Соорганизатор | одноразовая ссылка-приглашение от владельца | управление турниром без удаления и приглашения организаторов |
| Судья | одноразовая ссылка-приглашение от организатора | бюллетени только своих дебатов в этом турнире |
| Участник команды | заявка, подтверждённая организатором | выступать |
| Админ | `npm run admin:grant -- email@…` или другой админ | модерация турниров, оплата Pro, пользователи |

- Регистрация не принимает роль (поле `role` игнорируется) и требует согласия на обработку персональных данных.
- Создать турнир, подать заявку и принять приглашение можно только после подтверждения email.
  Сейчас письма печатаются в консоли сервера (`src/lib/mail.ts`); для продакшена замените транспорт на SMTP.
- Новый турнир виден в общем списке только после одобрения админом; при отклонении нужна причина, владелец получает письмо.
- Конфликт интересов блокируется: в одном турнире нельзя быть и участником команды, и судьёй/организатором.

## Уведомления

Каждое событие создаёт запись в центре уведомлений (`notifications`: тип + данные, текст собирается на сайте на RU/KZ)
и дублируется в Telegram тем, кто подключил бота (`src/services/notify.ts`). Получатели — по правам в конкретном турнире:

| Кому | Что |
|---|---|
| Участник (спикер/заявитель) | решение по заявке, жеребьёвка (аудитория, сторона, соперник, тема), итог раунда |
| Судья | назначение на дебат (роль, аудитория, ссылка на бюллетень), приветствие после принятия приглашения |
| Организаторы турнира | новая заявка, кто принял приглашение, одобрение/отклонение/удаление турнира |
| Админы | турнир ждёт проверки (с пометкой Pro) + лента всей платформы |

## Вход через Google

Кнопки «Войти / Зарегистрироваться через Google» появляются на сайте, только когда в `.env` заданы ключи.
Код — `src/routes/google.ts` (OAuth 2.0 + OpenID Connect на сервере: `state` против CSRF, `nonce` против повтора,
PKCE, проверка издателя/получателя/срока токена и `email_verified`). Токены Google не хранятся — только id аккаунта,
email, имя и фото (фото перекодируется в WebP, как обычный аватар).

**Настройка (один раз, в своём Google-аккаунте):**
1. Откройте [Google Cloud Console](https://console.cloud.google.com/) → создайте проект (например, «Debate.kz»).
2. **APIs & Services → OAuth consent screen**: тип *External*, название приложения, email поддержки;
   scopes — `openid`, `email`, `profile` (больше не нужно). Пока приложение в режиме *Testing*, войти могут только
   адреса из списка *Test users* — добавьте туда свои; для всех пользователей нажмите *Publish app*.
3. **APIs & Services → Credentials → Create credentials → OAuth client ID**, тип *Web application*:
   - *Authorized JavaScript origins*: `http://localhost:5173` (и боевой адрес, например `https://debate.kz`);
   - *Authorized redirect URIs*: `http://localhost:5173/api/auth/google/callback` (и `https://debate.kz/api/auth/google/callback`).
     Адрес строится из `CLIENT_ORIGIN`, он должен совпадать символ в символ.
4. Скопируйте *Client ID* и *Client secret* в `backend/.env` (секрет никому не пересылайте):
   ```
   GOOGLE_CLIENT_ID=1234-abc.apps.googleusercontent.com
   GOOGLE_CLIENT_SECRET=GOCSPX-...
   ```
5. Перезапустите бэкенд.

**Правила:**
- новый пользователь создаётся с подтверждённым email, именем и фото из Google и попадает в профиль дописать телефон, школу и город;
- если аккаунт с таким email уже есть — Google привязывается к нему (пароль продолжает работать). Если email этого аккаунта
  не был подтверждён, прежний пароль сбрасывается и все сессии завершаются: так чужой человек, заранее зарегистрировавший
  ваш адрес, не сохранит доступ;
- в профиле Google можно подключить (даже с другим адресом) и отключить — отключить можно, только когда задан пароль;
- у аккаунта «только Google» пароля нет: «Задать пароль» присылает ссылку на почту; удаление аккаунта подтверждается вводом email;
- о привязке/отвязке Google и смене пароля владельцу приходит письмо.

## Почта

Без настроек письма печатаются в консоль бэкенда. Чтобы они реально приходили (в том числе на Gmail), заполните SMTP в `.env`
(`src/lib/mail.ts`, шаблоны писем — `src/services/letters.ts`). Сбой почты не ломает запрос: ошибка пишется в лог.

**Gmail (для начала):**
1. В Google-аккаунте, с которого будут уходить письма, включите [двухэтапную аутентификацию](https://myaccount.google.com/signinoptions/two-step-verification).
2. Создайте [пароль приложения](https://myaccount.google.com/apppasswords) (16 букв). Обычный пароль от Gmail сюда не подходит.
3. Впишите в `backend/.env`:
   ```
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=465
   SMTP_USER=your.address@gmail.com
   SMTP_PASS=abcdefghijklmnop
   MAIL_FROM=Debate.kz <your.address@gmail.com>
   ```
Gmail отправляет до ~500 писем в сутки — для старта хватит; для боевого сайта лучше отдельный сервис рассылок
(SMTP-настройки те же, меняются только значения).

**Какие письма уходят:** подтверждение email, восстановление пароля, «задайте пароль» (для аккаунтов через Google),
«пароль изменён/задан», «добро пожаловать» (регистрация через Google), «Google подключён/отключён».
В тестах (`npm run test:e2e`) SMTP принудительно выключен, письма складываются в память и читаются через `/api/test/mail`.

## Telegram-бот

Бот — дополнение к сайту (`src/services/bot.ts`, `src/services/notify.ts`, `src/lib/telegram.ts`). Без токена он выключен,
сайт работает как обычно.

**Настройка (один раз):**
1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → имя (например, «Debate.kz») → username, который оканчивается на `bot` (например, `DebateKzBot`).
2. BotFather пришлёт токен вида `123456789:AA...`. **Никому его не пересылайте** (и не вставляйте в чаты) — с ним можно управлять ботом.
3. Впишите в `backend/.env`:
   ```
   TELEGRAM_BOT_TOKEN=123456789:AA...
   TELEGRAM_BOT_USERNAME=DebateKzBot
   ```
4. Перезапустите бэкенд — в консоли появится `Telegram bot @DebateKzBot started (long polling)`.

Бот работает через long polling (публичный адрес не нужен). Одновременно токен может опрашивать только один процесс.

**Что умеет:**
- привязка аккаунта: «Подключить Telegram» в профиле → одноразовая ссылка `t.me/<бот>?start=<токен>` (15 минут, хранится только хеш);
- подтверждение телефона кнопкой «Поделиться номером»: принимается только свой контакт, номера +7 7xx, один номер — один аккаунт;
- уведомления: жеребьёвка (аудитория, сторона, соперник, тема; судьям — роль и ссылка на бюллетень), решение по заявке, решение модерации;
- говорит на языке пользователя (русский или казахский): переключатель языка на сайте сохраняет его в аккаунте (`PUT /me/language`), в боте — `/lang` или кнопки;
- все уведомления центра на сайте дублируются в Telegram через `notify()`; тексты — в `src/services/botTexts.ts`, значения экранируются;
- команды `/next` (опубликованная жеребьёвка спикера, аудитории и бюллетени судьи, новые заявки организатора), `/tournaments`, `/me` (с кнопками языка и уведомлений), `/lang`, `/stop`, `/on`, `/help`;
- меню команд и описание бота выставляются на двух языках только при изменении и повторяются в фоне при сбое сети или 429;
- группы игнорируются; если пользователь заблокировал бота, чат отвязывается.

Сообщения пишутся только тем, кто сам подключил бота. В тестовом режиме (`NODE_ENV=test`) сообщения не уходят в Telegram,
а складываются в память — e2e играет роль Telegram через `/api/telegram/test/*` (в других режимах этих путей нет).

## API

| `GET /me/progress` | вошедший | прогресс спикера: баллы по речам, тренд, по позициям и темам, отзывы судей (только завершённые раунды) |
| `GET /certificates/:code`, `GET /me/certificates`, `GET /tournaments/:id/certificates` | все / вошедший / организатор | проверка сертификата по коду, мои сертификаты, все сертификаты турнира (выдаются при завершении) |
| `GET /tournaments/:id/checkin`, `POST …/checkin/code`, `POST …/checkin/reset`, `PATCH /teams/:id/checkin` | организатор | чек-ин: код для QR в зале, сброс, ручная отметка |
| `POST /checkin/:tournamentId` | вошедший участник турнира | отметить свою команду кодом с экрана (10 ошибок за 10 минут → 429) |
| `GET/POST /teammates`, `DELETE /teammates/:id`, `POST /teammates/:id/reply` | все / вошедший с подтверждённым email / автор или админ | поиск сокомандника: контакты не публикуются, отклик приходит автору уведомлением и в Telegram; 3 активных объявления, 30 дней, 20 откликов в сутки |
| `POST /safety-reports`, `GET /me/safety-reports` | вошедший | обращение о поведении (можно анонимно, 5 в сутки) и статус своих обращений |
| `GET /safety-reports`, `PATCH /safety-reports/:id` | админ или ответственный за безопасность | очередь обращений; анонимный заявитель скрыт и от них; смена статуса уведомляет заявителя |

## Правила, которые проверяет сервер

- Форматы (`services/formats.ts`, поле `format` при создании турнира, по умолчанию WSDC):
  - **WSDC** — 3 спикера по 60–80, ответная речь 30–40 (только 1-й или 2-й спикер), шаг 0,5;
  - **APF** (американский парламентский) — 2 спикера по 20–30, опровержение 10–15 (только 1-й спикер), шаг 0,5;
  - **POPPER** (Карл Поппер) — 3 спикера по 15–30, без ответной речи, целые баллы;
  - **BP** (британский парламентский) — 4 команды по 2 спикера в аудитории (ОП, ОО, ЗП, ЗО), 50–100 целыми, без ответной речи.
  Число спикеров в команде проверяется при заявке и ручном добавлении (`wrong_speaker_count` с `{ need }`).
- BP подробнее:
  - места 1–4 следуют из сумм команд (равные суммы — `tie_not_allowed`), дают 3/2/1/0 командных очка;
    если судья присылает `ranking`, он должен совпасть с суммами (`ranking_mismatch`);
  - панель совещается, бюллетень сдаёт только председатель (`chair_only` для боковых), он и есть результат дебата;
  - жеребьёвка — комнаты по 4: power — подряд по таблице, high_low — по одной команде из каждой четверти, random — случайно;
    позиции ОП/ОО/ЗП/ЗО распределяются так, чтобы команда реже повторяла позицию; в защищённых раундах одноклубники разводятся по комнатам;
  - число команд кратно 4 (`bp_teams_multiple_of_four` с `{ teams }`), swing-команд добавляется до трёх;
  - таблица сортируется по командным очкам (`points`), затем по баллам спикеров; 1-е место считается победой (`wins`).
- Ничьих нет; победитель = команда с большей суммой.
- Онлайн-турнир: у каждой аудитории может быть ссылка на видеозвонок (`tournaments.room_links`, только https); жеребьёвка
  кладёт её в дебат (`debates.online_url`), смена аудитории переносит ссылку этой аудитории, организатор может её убрать
  (`PATCH /debates/:id { onlineUrl: null }`). Ссылку видят только команды, судьи и организаторы — в кабинете, бюллетене,
  уведомлениях и Telegram; на публичной странице её нет.
- Аналитика для админов (`services/analytics.ts`, `GET /admin/analytics`): рост за 12 месяцев (аккаунты, турниры, команды), турниры
  и пользователи по регионам, статусы/уровни/форматы, вернувшиеся участники (2+ турнира), доля доведённых до конца турниров, средняя
  оценка, активные клубы. Только одобренные турниры и только общие числа; пол, возраст и другие личные данные не собираются.
- Сторож турниров (`services/watchdog.ts`, раз в час в процессе API; вручную — `POST /admin/watchdog/run`): за 3 дня до начала
  напоминает организаторам, если у отборочных раундов нет тем; через 1 день после окончания — «завершите турнир», через 5 дней —
  предупреждение; через 7 дней незавершённый турнир уходит в архив (`tournaments.abandoned_at`: скрыт с сайта, не считается в лимит
  активных) и владелец получает страйк. Страйк также за удаление турнира с командами менее чем за 3 дня до начала. 3 активных страйка
  (`organizer_strikes`) — `too_many_strikes` при создании турнира, аккаунт не блокируется. `GET /me/strikes`; админ: `GET /admin/strikes`,
  `POST /admin/strikes/:id/lift { note }` (в журнал). Завершение архивного турнира возвращает его на сайт; новые даты сбрасывают напоминания.
- Публичный профиль (`services/people.ts`, `GET /people/:userId`): карьера спикера (турниры, команда, место, место среди спикеров,
  победы/дебаты, средний и лучший балл), карьера судьи (турниры, раунды, председательство, плей-офф; средняя оценка — только при
  5+ отзывах) и награды. Только публичные турниры; закрытые раунды не учитываются до брейка. Переключатель «Скрыть профиль»
  (`users.profile_hidden`, `PATCH /me { profileHidden }`): страница — 404 для других, ссылки с имён спикеров и судей пропадают.
- Лучший спикер и лучший судья (`services/awards.ts`): `GET /tournaments/:id/awards` предлагает топ-3 спикеров по таблице (только
  выступившие во всех отборочных раундах) и топ-3 судей по оценкам спикеров (не меньше 3 отзывов; при равенстве — число отзывов,
  затем рейтинг от организатора). Организатор утверждает (`PUT /tournaments/:id/awards { kind, personId|null }`, `tournament_awards`);
  при завершении турнира (или сразу, если он уже завершён) выдаётся отдельный диплом (`certificates.kind = award`), победитель
  получает уведомление; смена выбора заменяет диплом. На странице завершённого турнира награды видны всем.
- Отзывы о турнире (`tournament_reviews`, `routes/reviews.ts`): при завершении турнира его спикеры и судьи получают
  «Оцените турнир»; оценка 1–5 с комментарием (`POST /tournaments/:id/review`, повторная отправка меняет). Публично
  (`GET /tournaments/:id/reviews`): средняя, распределение, рейтинг организатора по всем его турнирам и комментарии без имён —
  только «спикер» или «судья».
- Отзывы на судей (`judge_feedback`): спикер оценивает судей своего дебата 1–5 с комментарием, когда жеребьёвка опубликована
  (`POST /debates/:id/feedback`, повторная отправка меняет оценку); читают только организаторы
  (`GET /tournaments/:id/judge-feedback`: средняя, число и все комментарии с раундом и командой). Судья отзывы о себе не видит.
- Отбор команд (`services/selection.ts`): заявки без ограничения числа; публично видно «подано N заявок (мест M)»
  (`applications` в карточке, `GET /tournaments/:id/selection`). Итоговый состав — в пределах `maxTeams` и квоты на клуб
  (`club_quota`, `club_quota_reached`). Режим `selection_mode`: `manual` (организатор подтверждает; может поставить в лист ожидания —
  `waitlisted`), `first_come` (место сразу, пока есть, дальше — лист ожидания), `lottery` (`POST /tournaments/:id/selection/lottery`:
  случайный порядок на криптографическом генераторе, публикуется; места по порядку, остальные ждут; поздние заявки — в конец).
  Освободилось место (команду удалили, лимит или квоту изменили) — лист ожидания поднимается сам (в `first_come` и `lottery`).
- Модерация клубов (защита от фейков): новый клуб — `pending`; пока админ не одобрил, клуб не в каталоге, его страницу видят только
  участники и админы, в него вступают только по ссылке, заявки на вступление и на турниры не принимаются (`club_not_verified`).
  Отклонённый клуб участники исправляют (`PATCH /clubs/:id`) — он снова уходит на проверку. Жалоба на клуб — `POST /clubs/:id/report`.
  Админ: `GET /admin/clubs`, `PATCH /admin/clubs/:id { status, note }`, `POST /admin/clubs/:id/merge { intoId }` (дубль: участники,
  команды и история турниров переходят в настоящий клуб), `DELETE /admin/clubs/:id { reason }`, `POST /admin/club-reports/:id/resolve`;
  всё пишется в журнал. Существующие на момент миграции клубы считаются проверенными.
- Конфликты судей (`services/conflicts.ts`): судья не судит команду своего учебного заведения, своего клуба (по членству его
  аккаунта) и команды из личного списка (`PUT /judges/:id/conflicts { teamIds }`, таблица `judge_conflicts`). Жеребьёвка сажает
  председателем лучшего судью без конфликта (при нехватке меняет судей между комнатами), боковых — только без конфликта; если
  избежать не удалось, отчёт жеребьёвки говорит `judgeConflicts`. Ручное назначение с конфликтом — `judge_conflict`.
- Закрытые раунды (`rounds.silent`, `services/silent.ts`): организатор переключает любой отборочный раунд «Открытый / Закрытый»
  в любой момент, в том числе после жеребьёвки (`PATCH /rounds/:id { silent }`; раунды плей-офф — всегда открытые). Результаты закрытого
  раунда не видны публике до объявления брейка или завершения турнира — ни в таблице и рейтинге, ни в жеребьёвке (победитель скрыт),
  ни в «Моих дебатах» и прогрессе; уведомление об итоге такого раунда не отправляется. Организаторы видят всё; жеребьёвка, брейк
  и сертификаты считаются по настоящим результатам.
- Место турнира: регион (`tournaments.region`, 17 областей и Астана, Алматы, Шымкент — `src/lib/regions.ts`), город или село
  (если регион не передан, он находится по городу), район или адрес (`district`). Публичный список фильтруется `?region=`.
- Плей-офф (`services/playoffs.ts`):
  - брейк объявляется, когда турнир идёт и все отборочные раунды завершены (`POST /tournaments/:id/break`): лучшие `breakSize` команд
    таблицы получают посев 1..N (`teams.break_seed`), создаются раунды плей-офф (`rounds.kind = elimination`, `teams_in_round`);
    отменить можно, пока ни один раунд плей-офф не опубликован (`DELETE`, иначе `break_in_progress`);
  - сетка: 1–N, 4–5, 2–(N-1)… (1-й и 2-й посев встречаются только в финале); высший посев — Правительство;
    дальше проходит победитель дебата, в BP — две лучшие команды комнаты (финал BP — одна комната из 4);
    жеребьёвка следующего раунда — только после завершения предыдущего (`previous_round_unfinished`);
  - таблица и баллы спикеров считаются только по отборочным раундам;
  - с объявленным брейком турнир завершается только после финала (`playoffs_unfinished`); итоговые места (сертификаты, уведомления):
    чемпион — победитель финала, финалист 2-й, выбывшие в полуфинале — 3-и, в четвертьфинале — 5-е…, остальные — по таблице;
  - `GET /tournaments/:id/bracket` — посев, раунды плей-офф и чемпион (черновые раунды скрыты от публики), плюс `categories`.
  - Категории брейка (новички, младшие…): до брейка организатор задаёт до трёх категорий `{ key, name, size }`
    (`tournaments.break_categories`) и отмечает команды (`PUT /teams/:id/categories`). При объявлении брейка после открытого брейка
    каждая категория получает свою сетку из лучших отмеченных команд, не попавших в открытый (`rounds.category`, `teams.break_category`);
    команда играет только в одной сетке. Итоговые места считаются по открытой сетке, места в категории идут в сертификат
    (`certificates.break_category`, `category_place`: «1-е место в категории «Новички»»).
- Уровень турнира: `school`, `university` или `mixed` (смешанный); фильтр публичного списка по школе или вузу показывает и смешанные.
- Судьи голосуют каждый за себя со своего аккаунта, решает большинство; при равенстве голосов — председатель.
  Организатор и админ бюллетени не вносят и не меняют — только читают.
- Когда турнир завершён, сертификаты выдаются сразу, а участники (место команды), судьи и организаторы получают уведомление.
- Раунд публикуется только с темой и жеребьёвкой; завершается, когда у всех дебатов есть результат; после завершения бюллетени закрыты.
- Жеребьёвка: по силе (победы → баллы спикеров), без повторных встреч, с балансом сторон; один судья — одна комната за раунд; судья не судит свою школу. Судей нужно не меньше, чем комнат; ошибка `not_enough_judges` сообщает `{ need, have, teams }`.
- Организатор управляет только своими турнирами; заблокированный пользователь теряет доступ сразу.
- Этапы турнира: регистрация → идёт → завершён (назад в регистрацию — пока не опубликован раунд); нужен одобренный турнир и 2+ команды.
- Лимит команд не ниже числа команд в турнире; больше 20 — тариф Pro (оплату подтверждает админ).
- Swing-команда (добавляется при нечётном числе команд) не входит в таблицу, лимиты и счётчики команд.
- Тариф: все функции бесплатны; турнир больше 20 команд — Pro. Пока Pro не оплачен, турнир принимает не больше 20 команд (402 `payment_required`).
- Заявку на турнир можно подать только с клубом и командой в профиле (`club_required`); команда турнира запоминает клуб.
- Жеребьёвка: методы power / high_low / random, а для двухкомандных форматов ещё slide и fold (пары внутри группы с одинаковым
  числом побед, как в Tabbycat) и round_robin — круговая, каждый с каждым по кругу (`POST /rounds/:id/draw { method, protectClubs }`;
  в BP slide/fold/round_robin — `method_not_for_bp`). В раундах 1–2 по умолчанию команды одного клуба (или одной школы) не встречаются; если чистый вариант невозможен, делается минимум таких встреч, а ответ `report` говорит сколько (`services/pairing.ts`).
- Ответственного за безопасность назначает админ (`PATCH /admin/users/:id { safeguardingOfficer }`, пишется в журнал).
  В Telegram о новом обращении приходит только сигнал без подробностей.
